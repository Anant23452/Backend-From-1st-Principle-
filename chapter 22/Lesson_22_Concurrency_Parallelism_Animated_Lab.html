Thread costs and useful parallelism

Threads consume stack reservations and scheduling resources. Adding more threads helps some CPU tasks only until resource contention dominates.

Three models compared

OS threadsOS schedules; a blocked thread can be parked

Working pattern: non-blocking I/O

app.get('/jobs', async (req, res) => {
  const result = await pool.query(
    'SELECT id, title FROM jobs LIMIT 20'
  );
  res.json(result.rows);
});

Anti-pattern: blocking main JS thread

app.get('/slow', (req, res) => {
  let total = 0;
  for (let i = 0; i < 1e9; i++) total += i;
  res.json({ total });
});
Putting await before a resolved value won't relocate this heavy loop to another CPU.

Safe real SQL:
UPDATE internships
SET available_slots = available_slots - 1
WHERE id = $1 AND available_slots > 0
RETURNING id;
Zero returned rows means no seat left. This single UPDATE is atomic in PostgreSQL.
