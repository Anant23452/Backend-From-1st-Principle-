Extra coding explanation: Express global handler

class AppError extends Error {
  constructor(status, code, message) {
    super(message);
    this.status = status;
    this.code = code;
  }
}

// AFTER your routes:
app.use((err, req, res, next) => {
  if (res.headersSent) return next(err);
  const known = err instanceof AppError;
  const status = known ? err.status : 500;
  console.error({ requestId: req.id, status }); // safe metadata
  res.status(status).json({
    error: {
      code: known ? err.code : 'INTERNAL_ERROR',
      message: known ? err.message : 'Something went wrong',
      requestId: req.id ?? null
    }
  });
});

Additional instructor-inspired code. In Express 5, rejected async route promises are forwarded automatically; in older versions use explicit next(err)/async wrapper.

Why not retry forever?

Repeated calls can overload a failing service and worsen an outage. Limit attempts, use timeouts, honor Retry-After when present, and consider a circuit breaker.

Why do idempotency keys matter?

If a provider completed an operation but its HTTP response was lost, retrying might execute it twice. A stable idempotency key helps the provider deduplicate supported operations.
