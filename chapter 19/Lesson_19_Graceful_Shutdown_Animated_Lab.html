The teacher's first example

Situation

Payment in progress

The old server is processing a payment while a new version is being deployed.

Problem

Abrupt termination

The request may be interrupted, leaving the client uncertain whether the operation succeeded.

Solution

Graceful shutdown

Stop sending new requests to the old server and let existing requests finish within a deadline.

Added engineering insight: Graceful shutdown is not a replacement for idempotency, database transactions, or durable jobs. Together, these help prevent lost or duplicated work.

The teacher's restaurant analogy

Restaurant
  • Reception stops admitting new guests.
  • Existing guests finish their meal.
  • Staff clean up and close the restaurant.
Backend
  • HTTP server/load balancer stops routing new requests.
  • Active requests or transactions finish.
  • Connections, files and workers close; process exits.

Signals at a glance

Catchable

SIGTERM

A deployment or process manager asks politely for a controlled stop.

Catchable

SIGINT

Ctrl+C interrupts a terminal process. Use the same shutdown routine.

Not catchable

SIGKILL

Forced termination; the process has no chance to run a cleanup handler.

Experiment A — Gentle stop

Node.js translation (added teaching code)

The teacher shows a Go implementation; this simplified Express version demonstrates the same conceptual sequence.

import express from 'express';
import { Pool } from 'pg';

const app = express();
const pool = new Pool({ connectionString: process.env.DATABASE_URL });
let draining = false;
let stopping = false;

app.get('/ready', (req, res) => res.sendStatus(draining ? 503 : 200));
const server = app.listen(process.env.PORT || 5000);

async function shutdown(signal) {
  if (stopping) return;
  stopping = true;
  draining = true;
  console.log(`${signal}: refusing new work`);

  const watchdog = setTimeout(() => {
    server.closeAllConnections();
    process.exit(1); // exceeded shutdown budget
  }, 30_000);
  watchdog.unref();

  try {
    await new Promise((resolve, reject) =>
      server.close(err => err ? reject(err) : resolve())
    );
    await pool.end();
    clearTimeout(watchdog);
    process.exitCode = 0;
  } catch (err) {
    console.error('Shutdown error', err);
    process.exitCode = 1;
  }
}
process.on('SIGTERM', () => void shutdown('SIGTERM'));
process.on('SIGINT', () => void shutdown('SIGINT'));
From the teacher: In Go Tasker, main.go waits for the interrupt signal and calls a shutdown method with a deadline. server.go closes HTTP, DB pool and the Redis-backed job processor in the shown example.
Added caution: For a system with active queue workers, finish their jobs while database connections are still available. Normal HTTP server shutdown does not automatically close WebSocket upgrades or control outside worker processes. Your Render deployment's termination budget must be considered.
