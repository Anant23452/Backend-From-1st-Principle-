Why the order matters

If authentication ends with res.status(401).json(...), all later middleware and the controller are skipped. Earlier logging still ran; later logging did not.

app.use(requestId);
app.use(express.json());
app.get('/api/jobs', authenticate,
        rateLimit, jobsController);
app.use(errorHandler); // after routes
Production note: real Express executes registered middleware in matching order; router handlers also participate in that stack. The global four-argument error handler normally appears after routes. CORS browser controls are not a substitute for server authorization.

What the server should trust

Never use a global variable for currentUser. Concurrent requests can overwrite one another. Use request-scoped storage such as req.user, res.locals, or an appropriate async context system.
// after verifying JWT signature and claims
req.user = { id: verified.sub };
// controller uses verified identity
const ownerId = req.user.id;
MODULE 04 · RESPONSIBILITIES & REFACTORING

Which layer should contain this line of code?

Select a layer to see its exact responsibilities, then classify real lines of code. The goal is to make backend architecture intuitive rather than memorized.

Code detective

A readable Newbert folder structure

src/
  app.js
  routes/jobs.routes.js         # endpoint mapping
  middleware/auth.js            # shared auth
  middleware/errors.js          # error mapping
  controllers/jobs.controller.js# HTTP boundary
  services/jobs.service.js      # business rules
  repositories/jobs.repo.js     # PostgreSQL access
  db/pool.js                    # connection pool

This is a useful structure, not a framework requirement. Start simple and only add layers when they reduce complexity.
