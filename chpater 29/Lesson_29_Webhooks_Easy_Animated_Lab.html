Lesson 29 · First principles

Webhooks are a doorbell for your backend.

Imagine a student pushes code to GitHub while Newbert is running on Render. Instead of Newbert repeatedly asking “Any new commits?”, GitHub knocks on a special URL and sends the event.

Webhook: an HTTP request another service sends your backend when a selected event occurs. Your backend needs a public HTTPS receiving endpoint, not an always-open browser tab.

Memory line: A REST API is often a call your app makes. A webhook is often a call another service makes to your app.

Experiment 3

Can Newbert trust this message?

Anyone can send JSON to a public URL. A real provider can attach a cryptographic signature, and Newbert must verify it before trusting the message.

Choose a scenario and click Verify. The demo simulates the verification rules rather than computing cryptographic signatures.

In actual Node.js code: verify the provider's signed raw request bytes with its documented algorithm, use a timing-safe comparison, and add event-ID deduplication. Some protocols also sign a timestamp; others do not.
